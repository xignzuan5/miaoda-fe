# 页面模板抽取与续写规则

## 抽取范围

抽取对象包括设计值、组件配方、页面模板和应用壳层。用户举出的差异仅是检查入口，不能作为完整性上限。
阅读主题入口、全局 CSS、字体资源、组件覆盖、布局、路由、菜单和多个代表页面，追踪实际生效的样式优先级。
按项目实际功能检查颜色、排版、图标、尺寸、间距、边框、阴影、透明度、层级、动效、滚动、溢出、定位、响应式、主题、密度、交互状态及资源加载。
对每类记录已覆盖、未发现、不适用或未验证及证据；扫描到值不等于理解语义，编译通过不等于视觉一致。

## 壳层复用

先定位现有 AppShell、Layout、children/Outlet 插槽及路由装配点。已存在可用壳层时直接复用，页面代码只进入内容插槽。
顶栏、侧栏、全局搜索、通知、主题切换、面包屑、鉴权、Provider、收起状态和滚动归壳层所有。新增页面不复制这些代码，也不嵌套第二个壳层。
路由、菜单、权限和面包屑按现有项目机制做最小增量；不把原有分散配置强制重构成新路由系统。
只有目标项目缺少壳层时才移植代码模板，并同时处理依赖、资源、状态和宿主适配。应区分原样源码快照、可运行适配版与视觉验证状态。

## 内容模板

从实际存在的页面选取列表、选项卡、设置表单、详情、仪表盘、两列详情和多列卡片网格等模板，不预设所有项目必须拥有这些类型。
模板必须交付可编译代码，提供 title、actions、filters、tabs、content、pagination 等实际需要的插槽；业务数据通过 props 输入，事件通过回调输出。
列表是否包卡片、表单最大宽度、标题是否显示、滚动容器和响应式规则按模板分别记录，不推广为全站规则。
模板登记表记录名称、代码入口、来源页面、适用场景、壳层依赖、插槽、不可变区域、可变区域、路由接入位置、资源依赖和验证状态。

两列和三列必须按源码证据区分“页面布局”和“内容网格”：

- 两列模板只抽取列容器、轨道配置、间距和堆叠规则，主区/辅助区由插槽提供。不同来源页若存在 8/4、5/7 等不同轨道比例，比例必须作为模板参数或变体登记，不能被平均值替换。
- 三列模板可以来自实际反复出现的 `md=4` 卡片网格，但只能沉淀列数、断点、间距、对齐和卡片插槽；不能把 APM、集成或数据源卡片的业务字段写死进通用模板。
- 若项目只发现局部三列网格，没有发现三列“整页框架”，登记名称应写成“三列卡片网格/内容网格”，不要误称为三列页面壳层。
- `layout-inventory.json` 只代表扫描到的布局证据。模型必须回到来源文件确认父子层级、滚动归属、可访问性顺序、响应式折叠和是否由 UI 库组件负责。

## 执行“生成产品列表页”

1. 读取项目模板登记表和对应代码，确认现有壳层挂载位置。
2. 有列表模板就复用其内容结构，传入产品字段、筛选条件、表格、分页和事件。
3. 有壳层则只新增内容页及路由菜单注册；仅面包屑标签/菜单激活状态随路由变化。
4. 检查生成页没有重复顶栏、侧栏、Provider 或双重内容区 padding。
5. 编译并检查路由直达、菜单激活、面包屑、主题/收起状态和代表视口的运行样式。字体需确认实际加载，不能仅检查 font-family 字符串。

## 交付边界

正则扫描只提供候选证据。完整抽取还必须由模型阅读上下文，交付源码支撑的模板代码、登记表与覆盖报告。
模板代码仅引用已登记的资源和依赖；未经验证的模板不得标为像素一致或 stable。缺少证据时保留缺口，禁止将推测值包装成已提取事实。
