# 妙搭固定技能安装指令

妙搭的“告诉妙搭创建技能”入口是对话式安装器。使用下面的固定指令时，Agent 只能读取并注册项目中已经写好的定义，不得自行设计、补写、删改或改名。

## 安装 `/页面开发`

```text
请把当前项目中已经写好的固定技能注册为项目技能，不要重新设计或改写技能内容。

唯一来源文件：design-system/miaoda/extensions/slash-page-development.md
技能名称必须是：页面开发
技能命令必须是：/页面开发

执行要求：
0. 先检查并修改当前妙搭应用项目根目录的 `AGENTS.md` 或 `CLAUDE.md`。如果不存在，按 `design-system/docs/miaoda-agent.md` 的固定规则创建；如果已存在，只更新 `design-token-system` 标记区，不改动标记区之外的用户内容。写入后必须回读确认步骤 1 已存在。
1. 再读取上述唯一来源文件；如果文件不存在、无法读取或内容不完整，立即停止并报告，不要根据自己的理解补写。
2. 将文件中的 frontmatter、描述、执行规则、验证规则和示例原样作为技能定义来源。
3. 不得增加、删除、改写、翻译、摘要或重排任何规则；不得把“页面开发”改成其他名称。
4. 创建后回显实际注册的技能名称、命令和来源文件路径，并说明是否完整采用了来源文件。
5. 后续执行该技能时，每次都必须重新读取来源文件和 `design-system/docs/miaoda-agent.md`；来源文件是唯一规则源。
```

## 安装 `@设计变量解析`

如果当前妙搭租户支持创建自定义 `@` 插件，使用同样的方式注册：

```text
请把当前项目中已经写好的固定插件定义注册为 @ 插件，不要重新设计或改写插件内容。

唯一来源文件：design-system/miaoda/extensions/at-design-variable-parser.md
插件名称必须是：设计变量解析
插件触发方式必须是：@设计变量解析

先读取来源文件；文件不存在或无法完整读取就停止。必须原样采用文件中的规则、产物和完成检查，不得自行补写或删改。创建后回显实际注册名称、触发方式和来源文件路径。
```

如果当前租户没有自定义 `@` 插件入口，不要把它偷偷改成另一个技能。此时固定回退方式是使用官方 `@文件解析`，附加 `at-design-variable-parser.md` 和审计文件，并要求 Agent 严格按附件原文执行。

## 首次接入时执行 `@设计变量解析`

完成步骤 1 的项目规则写入和 `/页面开发` 原样注册后，再执行下面的固定指令。它负责生成/刷新 `/页面开发` 所需的步骤 2–5 资料，不负责创建或改写页面技能：

```text
请执行当前项目中已经写好的固定 @设计变量解析流程，不要自行设计另一套抽取规则。

唯一来源文件：design-system/miaoda/extensions/at-design-variable-parser.md

执行顺序：
1. 先回读项目根目录 AGENTS.md 或 CLAUDE.md，确认步骤 1 已存在；不存在或无法读取就停止。
2. 若当前环境可以执行项目命令，在项目根目录运行 npm run project:init，并回显真实返回码、扫描统计和产物更新时间；没有命令执行能力时必须明确报告“确定性扫描未执行”，不得把文字推断当成扫描结果。
3. 读取最新源码、运行时样式、组件覆盖、字体资源、路由/菜单/权限和代表页面。
4. 生成或刷新 /页面开发 读取清单中的步骤 2–4 文件，并将步骤 5 中真实存在的壳层、插槽和列表/选项卡/表单/详情/仪表盘/两列/三列模式登记到 page-templates.json；不要复制完整业务页面。
5. 每条 Token、Recipe 和模板都记录来源与状态；缺失或冲突内容放入 candidate/unresolved/not-found/not-verified，不得凭经验批准。
6. 运行项目规定的校验和构建，用中文回报读取来源、更新文件、扫描证据、已确认项和未验证项。

完成后再调用 /页面开发；不要在本次抽取完成前直接实现新页面。
```
