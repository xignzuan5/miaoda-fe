# 提取 Design Token

从现有项目生成有源码证据的 Token 清单和可审核设计规范。除非用户明确要求迁移样式，否则对目标项目只读。

## 工作流程

抽取必须覆盖项目实际样式范围，不限于用户举例。除数值盘点外，阅读布局、路由、菜单和代表页面，识别已有壳层及内容区插槽，交付几个有源码依据的可编译页面模板、模板登记表和覆盖缺口报告。现有壳层优先登记复用；跨项目移植需声明依赖和适配边界，不得将正则扫描完成等同完整规范完成。

1. 识别 CSS 系列文件、CSS-in-JS、主题对象、框架配置、组件库、字体、图标和目标平台，并遵守项目现有指令。
2. 运行 `scripts/extract-tokens.mjs --root <项目> --output <审计目录>`，生成确定性的第一轮清单。输出目录不得位于依赖或构建目录中。
3. 结合源码上下文检查高频值，排除一次性布局值、第三方代码、生成代码、演示和测试夹具。
4. 提议正式 Token 前阅读 [Token 契约](references/token-contract.md)，遵循字段、命名、分层和审核状态。
5. 从原始值建立 Primitive 候选，再依据用途建立 Semantic Token。只有组件确实拥有稳定例外或内部决策时才建立 Component Token。
6. 检查交互状态、亮色/暗色/高对比度一致性、响应式、排版、层级、动效、密度、焦点和无障碍证据。
7. 同时交付机器可读候选和中文设计规范。明确标记推断映射与未解决聚类，不得仅按数值相似度猜测品牌语义。
8. 用户要求迁移时才逐步修改使用方，保持视觉行为并运行测试和视觉检查；否则在审计与提案完成后停止。

## 必需产物

- 原始清单：值、分类、出现次数和源码位置。
- 语义结构清单：标题层级、页面地标、表格结构和组件使用位置，供模型结合上下文建立页面与组件配方。
- 布局证据清单：MUI/Tailwind/CSS 栅格列定义、响应式断点和来源位置；它是发现线索，不自动代表页面模板。
- 字体资源清单：字体族声明、外部/本地资源地址、字重和来源；声明不等于浏览器已加载，需运行时验证。
- Token 候选：别名、中文描述、层级、状态、范围、平台和来源证据。
- 中文设计规范：基础、语义、组件状态、主题、响应式、无障碍、例外和待决项。
- 页面模板代码与登记表：只抽取壳层的固定区域、内容模板的插槽和可配置布局参数；不得把完整业务页面复制进模板。
- 迁移映射：现有硬编码或变量到建议 Token 名称。

不得统计压缩、第三方、锁文件、生成、构建或依赖文件。不得读取环境变量或凭据文件，发现疑似秘密值时也不得写入报告。
